# Operating the qualification core

Read README.md and docs/OPERATIONS.md. Flow: guided ICP -> human calibration -> saved evidence -> company fit -> person fit -> CSV. One business per installation; multiple named ICPs. This tool stops at the CSVs: no email discovery, activity checks, drafts or campaign imports exist here.

Validation: `uv run python -m unittest discover -s tests -v`. Python only via `uv run`. Keep secrets in .env and never print them. Never make paid provider calls to validate code.

Onboarding (skills/icp-onboarding/SKILL.md): ask one intake question per message. Record each answer with `uv run python -m src.profiles answer --profile <name> --key <key> --value <answer>`; `next-question` resumes. Read the website when given, label proposals as inferred and wait for corrections. Never turn an inferred preference into a mandatory criterion. Keep company location, served markets, person location, employee headcount and department headcount distinct. Optional outreach answers may be skipped. Profiles live in profiles/<name>/client-profile.yaml with icp-prompt.txt and version archives, local and git-ignored. An old icp.yaml cannot be loaded; redo the interview.

Calibration (skills/icp-prompt-builder/SKILL.md): rounds of exactly 10 saved companies, scored by in-session subagents, never a separate model API. `uv run python -m src.profiles round --round N` prints the full prompt and every decision with its reasons; show all of it and wait for the human's actual feedback. Never create approval yourself. Two consecutive approved rounds without corrections lock a version; corrections reset the streak; a changed profile or prompt creates a draft version. Fewer than 10 companies with evidence is a shortage: report it, keep qualification provisional, and collect more only when authorized. Abandoned rounds free their companies.

Runs: `uv run run.py --slug <slug> --icp profiles/<name>/client-profile.yaml --post <URL>` (or `--profile`). A single post link (linkedin.com/posts/..., /feed/update/..., lnkd.in/...) means `--post`; a personal profile link means `--profile`; company pages are not supported, say so. Until the ICP is locked use `--sample` (one post, at most 10 reactions, no comments, $0.10) or `--skip-harvest` on saved data. `--dry-run` prints the harvest, profile and company caps and makes no calls; state that preview before an authorized paid run. Defaults: harvest $1; 10 profile lookups / $0.25; 10 company lookups / $0.25. Company enrichment is on by default, keyed on current employment identity; name searches need corroboration. `--getleads` is optional gap-filling. Unknown provider outcomes are held: check the provider before `--retry-unknown`.

Scoring is evidence-bound: `uv run python -m src.qualify --slug <slug> --icp <profile> --dump` (run.py with `--skip-harvest --no-resolve --no-enrich --dump` is the same). Judge output/<slug>/assessment-packet.json: companies first, then people at companies that qualified in the same segment. Copy `score_context` exactly, cite supplied observation IDs and exact quotes. Confidence below 0.6 or missing mandatory evidence means needs_review; missing preferred evidence never blocks. Never override mandatory criteria with comments or a number. Submit with `--scores` and rerun until nothing is pending.

Every run ends with `uv run src/summary.py --input output/<slug>/all_leads.csv`; paste it, the user does not open CSVs. qualified_leads.csv holds only locked-ICP, fully qualified, unsuppressed people; a draft ICP yields provisional rows only.

Ledger (`src/ledger.py`): `suppress` customers, teammates and opt-outs when the user names them; `mark` manual outreach or replies when they report them; `stats` for counts. Suppressed or campaigned people never appear in qualified_leads.
