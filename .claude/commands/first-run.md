# Cheap first run (Apify + scoring only)

Run one small, paid harvest to confirm keys, scoring and the ICP before any real sweep.

1. Preconditions: `.env` has a non-empty `APIFY_TOKEN` (check names only, never values), `icp.yaml` exists, and you have a target. Ask for a profile URL or a post link, or use the first non-comment line of `targets.txt`. Supported inputs: a personal LinkedIn profile (`linkedin.com/in/...`, such as a competitor founder or an influencer your buyers follow) or one specific post (`linkedin.com/posts/...`, `/feed/update/...`, or an `lnkd.in` link to one). Company pages (`linkedin.com/company/...`) are not supported. If something is missing, point at `/setup` and stop.
2. Decide the harvest mode from the link. A post link (`linkedin.com/posts/...`, `linkedin.com/feed/update/...`, or `lnkd.in/...`) means `--post`: only that one post is scraped, never the author's recent posts. A profile link (`linkedin.com/in/...`) means `--profile` with `--max-posts 3`.
3. State the spend before running and wait for an explicit yes. Profile mode: 3 posts, 20 reactions and 10 comments per post, a few cents of Apify. Post mode: up to 100 reactions and 50 comments at about $0.004 per engager (full profiles included), so about $0.60 at most, hard cap about $0.85.
4. Harvest, nothing else yet:
   - profile: `uv run src/harvest.py --profile <url> --slug scraping-test-01 --max-posts 3 --max-reactions 20 --max-comments 10 --posted-limit month`
   - post: `uv run src/harvest.py --post <url> --slug scraping-test-01 --max-reactions 100 --max-comments 50`
5. Score. If `OPENAI_API_KEY` is empty (the default), you do it: `uv run src/icp.py --slug scraping-test-01 --icp icp.yaml`, then `uv run src/rank.py --dump --slug scraping-test-01`, judge every numbered engager with the rubric in `src/rank.py` SYSTEM (be stingy; the user's own profile and the source author score 1), and write `output/scraping-test-01/scores.json` as `{"results": [{"i", "score_context", "icp_fit", "qualification_reason", "needs_review", "intent", "intent_reason", "evidence_comment", "clean_title", "company_guess"}]}` with one object per pending engager (copy `score_context` exactly from the dump; `evidence_comment` = the number of the comment `cN` your intent rests on, or null). Before running it, state the resolve spend: `uv run src/rank.py --slug scraping-test-01 --scores output/scraping-test-01/scores.json` then `uv run src/resolve.py --slug scraping-test-01 --min-fit 3 --dry-run` prints how many fit-3+ candidates with hidden ids it would resolve at $0.004 each (post-mode harvests usually need none); if more than 10, the Apify free plan needs `--resolve-batch 10` on the run.py command. Then `uv run run.py --slug scraping-test-01 --skip-harvest --icp icp.yaml --scores output/scraping-test-01/scores.json`. Always pass `--scores` here (inside Claude Code run.py refuses to score on its own). If run.py stops with "need judgments for current profile evidence" or rejects a stale score_context, that is the second scoring pass: run `uv run src/rank.py --dump --slug scraping-test-01`, rescore only the listed indices using their new location and employer (apply the ICP geos and disqualifiers), save scores.json, and rerun the same command. Already-resolved profiles are not paid again. Do not add `--find-emails`, `--supabase`, `--campaign-id` or `--activity` on this run.
6. The run ends with a summary (counts, fit distribution, top rows by name). Paste it into your reply; the user does not open CSVs. Add the row count, how many qualified rows have public profile URLs, the `Profile lookups` line (run.py looks up opaque `/in/ACoAA...` candidates at $0.004 each before final scoring; if a lookup fails the run stops with exit 3 before any export, keeps what succeeded, and a rerun retries only the failures; on the free plan rerun with `--resolve-batch 10`), and spot-check a few titles against the ICP.
7. If scoring looks off, propose edits to `icp.yaml` or to specific scores and apply them only after the user agrees. Rescoring is free: edit `scores.json`, rerun `run.py --skip-harvest ...`; profiles already looked up are never paid for again. Never re-harvest just to rescore.
8. Profile lookups already ran inside `run.py`; their results live in `engagers.json` and `ranked_engagers.csv`. To preview or retry only that stage: `uv run src/resolve.py --slug scraping-test-01 --dry-run`, state the estimate, then rerun without `--dry-run`. Optional activity check, only if `TYPESAFE_API_KEY` is set: run `uv run src/activity.py --input output/scraping-test-01/ranked_engagers.csv --output output/scraping-test-01/activity.csv --dry-run`, report the eligible count, the estimate and the hard cap, and wait for a yes. Then rerun without `--dry-run` and with `--limit 10`, and show `uv run src/summary.py --input output/scraping-test-01/activity.csv`.
9. If the user asks for better ICP evidence and has GetLeads, preview `uv run src/getleads.py --slug scraping-test-01 --dry-run --max-lookups 10`, state the lookup/credit count, then add `--getleads --getleads-max-lookups 10` to the saved-harvest run. Keep this optional. GetLeads uses plan credits/fair-use, not its $0.012 scraping product. Rescore any changed evidence using new contexts before continuing. An unmatched lookup means evidence is still unknown; it does not disqualify the person. Pending/unknown submissions must be checked before an explicit retry.
10. Report every artifact path. Do not mark anyone as contacted; nothing has been sent.

Scoring uses current LinkedIn role titles, employer identities, dates and role descriptions before database titles. `needs_review` is a required boolean in every score: use true for missing required ICP facts or unresolved conflicts, and explain the missing fact in `qualification_reason`. A supported disqualifier is `not_qualified`; a supported match above the threshold is `qualified`. Missing data alone is not a rejection. Company alignment is exported as `getleads_company_alignment`: identifiers are strongest; `matched_name_only` is lower-confidence database evidence, while `conflict`/`unconfirmed` company facts are excluded from scoring. Team headcount cannot be inferred from company headcount. Review holds block activity, drafts, email discovery and imports regardless of fit. Old scores must be reviewed against a fresh dump after this rubric upgrade; saved harvests and provider caches are reusable.
