# First-time setup (no paid calls)

Get this repo ready to run without spending any API credits.

1. Check `uv --version` (uv and Python 3.11+ are required). Run `uv sync` to install dependencies into `.venv`.
2. Scoring choice. Ask the user which judge scores the engagers: (a) you, in this session, with the rubric in `src/rank.py` and no key (default); (b) automatically via their Claude subscription through the `claude` CLI (`LLM_PROVIDER=claude` in `.env`, no key, needs `claude` installed and logged in); or (c) automatically via OpenAI gpt-4.1-mini (`OPENAI_API_KEY`, a few cents per run). Only mention `OPENAI_API_KEY` below if they choose (c).
3. If `.env` is missing, `cp .env.example .env`. Report only the NAMES of empty keys, for example with `grep -E '^[A-Z_]+=$' .env | cut -d= -f1`. Never read, print or echo values, and never ask the user to paste a key into chat. Explain what each key unlocks: `APIFY_TOKEN` is the minimum for harvesting; `OPENAI_API_KEY` only for the OpenAI scoring choice; `FIRECRAWL_API_KEY` for `--domain` ICP derivation; `PROSPEO_API_KEY` for `--find-emails`; `TYPESAFE_API_KEY` for `--activity`; `SMARTLEAD_API_KEY` only for an actual campaign import; `SUPABASE_*` only for the optional database. Ask the user to fill `.env` in their editor and tell you when done.
4. ICP: if `icp.yaml` exists, summarize it and ask whether to keep it. Otherwise `setup_icp.py` is interactive (website first, then nine pre-filled questions) and cannot be driven from here, so offer two options: the user runs `uv run setup_icp.py` in their own terminal, or you do the intake in chat: ask for their website and read it, propose an ICP, then confirm the nine answers (what they sell; best 1-3 customers; buyer job titles, expanded with the synonyms that appear in LinkedIn headlines; company size as numbers; industries in; industries out; countries; buying triggers; hard disqualifiers) and write `icp.yaml` with the keys `titles, industries, industries_out, company_size, geos, triggers, disqualifiers, best_customers, summary`, matching `icp.example.yaml`. Show the file before writing it. Never invent an ICP from unrelated projects.
5. If `targets.txt` is missing, copy `targets.example.txt` to `targets.txt` and ask for competitor or influencer profile URLs, or specific post links, to add. Supported inputs: a personal LinkedIn profile (`linkedin.com/in/...`, such as a competitor founder or an influencer your buyers follow) or one specific post (`linkedin.com/posts/...`, `/feed/update/...`, or an `lnkd.in` link to one). Company pages (`linkedin.com/company/...`) are not supported.
6. Do-not-contact list (optional, no spend). Ask whether there are existing customers, teammates, partners or competitors who must never be contacted. Add them to the local ledger with `uv run src/ledger.py suppress --csv <file> --reason customer` (columns `linkedin_url` and/or `email`), `--domain <company.com> --reason teammate`, or `--url <profile> --reason <why>`. Explain that the ledger (`data/ledger.sqlite`) also remembers everyone across runs, so nobody is pushed into a second campaign.
7. Mention that `activity.toml` (activity-intel fetch caps, threshold, question wording) exists and is user-owned; do not edit it.
8. Run `uv run python -m unittest discover -s tests -v` and report the result as it is. Finish by pointing the user at `/first-run` for a cheap live test.
