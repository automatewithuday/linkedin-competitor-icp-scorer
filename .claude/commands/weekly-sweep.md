# Weekly warm-lead sweep

Only add `--getleads` when the user wants the optional ICP evidence enrichment and has GETLEADS_API_KEY. Preview the candidate count and state `--getleads-max-lookups` for each slug; this cap persists across retries. Match/partial/miss caches are shared across targets for 30 days. Run new rank.py dumps for any changed evidence before continuing in-session scoring. GetLeads uses plan credits/fair-use, never its scraping wallet; unknown billable outcomes are held for provider review.

Read README.md, docs/OPERATIONS.md and targets.txt. For each nonblank, noncomment target (a personal profile or one post; company pages are not supported) run the documented pipeline with the user's ICP and a distinct target/date slug. A profile URL is harvested with `--profile` (10 posts by default); a post link (`linkedin.com/posts/...`, `/feed/update/...` or `lnkd.in/...`) is harvested with `--post` and only that post is scraped. Cap Prospeo at 100 qualified lookups per target unless the user has specified other limits.

Scoring: if `OPENAI_API_KEY` is empty, harvest first (`src/harvest.py`), then `src/icp.py`, then `src/rank.py --dump`, judge every engager with the rubric in `src/rank.py` SYSTEM, write `output/<slug>/scores.json` with a concise `qualification_reason` and `intent_reason` for every accepted and rejected person, and each row's `score_context` copied exactly from the dump, and continue with `run.py --slug <slug> --skip-harvest --icp icp.yaml --scores output/<slug>/scores.json ...` (always pass `--scores`). If run.py stops because candidates gained location/company, including a partial lookup failure, rescore those indices and rerun the same command. With the key set, one `run.py` call does it all.

CSV is always produced. `run.py` looks up opaque `/in/ACoAA...` candidates before final scoring ($0.004 per profile; include it in the spend you state; preview with `uv run src/resolve.py --slug <slug> --dry-run`). If a lookup fails the run stops before any export; rerun the same command to retry only the failures. Add --activity only when the user has set TYPESAFE_API_KEY and wants the LinkedIn activity check (run the dry run and state the estimate first). Add --supabase only when the user has configured the database and requested it. If a Smartlead campaign or HeyReach list is supplied, generate a preview. Execute the import only when the user has authorized that campaign import; an active campaign may send emails.

The ledger gate means a person who engaged with several targets is pushed at most once, and anyone already imported to a campaign or suppressed is skipped automatically; rows scored in an earlier sweep with unchanged evidence are reused instead of rescored. After the last target, run `uv run src/ledger.py stats` and report how many people appeared across several targets. Every run ends with a summary (counts and top rows by name). Paste each target's summary into your reply; the user does not open CSVs. Report per-target errors and artifact paths. Reuse completed Prospeo checkpoints when recovering an enrichment stage. Do not rerun paid harvests merely to retry a destination export. Do not mark harvested leads as contacted. Smartlead duplicate/block/unsubscribe checks must remain enabled. This command does not install a recurring scheduler.
